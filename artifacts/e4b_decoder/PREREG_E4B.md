## 1. Adapters
- Backbone `Qwen/Qwen2.5-0.5B` (base, not instruct) @ `060db6499f32faf8b98477b0a26969ef7d8b9987`, loaded as `AutoModelForSequenceClassification` (= `Qwen2ForSequenceClassification`).
  **Pooling: the last non-pad token** (HF rule: the rightmost token ≠ `pad_token_id`). `pad_token = <|endoftext|>` (id 151643, set in the model config), right padding.
  The tokenizer adds no BOS/EOS, so the pooled token is the last text token. Fallback (only if Qwen fails to load): another ≤ 0.5B decoder, documented as a deviation.
- Inputs: E1b `tasks.py` input construction (unmodified). Single texts are tokenized as is. Pairs use `tokenizer(a + "\n", b)`: plain concatenation, longest-first truncation at **256**.
  Probe: imdb has 40% and yelp 20% of examples > 256 tokens (truncated); all other tasks have < 0.5%.
- **LoRA** r = 8, α = 16 (scaling 2), dropout 0.1 on `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj` in all 24 layers = **168 LoRA layers** (asserted).
  **Classification head** `score` (Linear 896 → num_labels, no bias, seeded random init) is fully trained (`modules_to_save=["score"]`) and saved with each adapter (like E1b's heads).
- Recipe: AdamW, batch 32, weight decay 0.01, linear schedule, warmup = min(500, round(0.1·max_steps)).
  **fp32 master weights + bf16 autocast** (Trainer `bf16=True`), dynamic padding. imdb and yelp use micro-batch 16 × 2 accumulation.
  OOM fallback: halve the micro-batch and double the accumulation (automatic retry). The effective batch is always 32. lr: from the pilot (§1a).
- **Budgets** (table in json; ≈ 20.2k steps per seed):
  - pool ≤ 10k (cola, mrpc, stsb, rte, wic, trec): the full pool, 10 epochs, exactly the E1b steps.
  - larger pools: min(pool, 50k) examples, taken as the first examples of E1b's seed-0 permutation after the held-out 1,000 (nested inside E1b's 60k subset).
    1 epoch, or 2 epochs if the pool is < 30k (scitail, imdb).
  - The held-out 1,000 TRAIN examples are E1b's (asserted by sha256).
  - Eval sets > 5,000 use a seeded 5,000 subset: `sorted(default_rng(1).choice(n, 5000))`.
- Seeds 0 and 1 (§1b). The seed controls LoRA-A init, head init, dropout and data order. Splits do not depend on the seed.
- Collapse monitoring: loss logged every 25 steps, with the training-label prior entropy. Collapsed adapters are **not retrained**; integrity decides (§2).

### 1a. Pre-registered pilot (documented pre-step; part of this prereg)
- sst2 (1,563 steps) and rte (470 steps), seed 0, main recipe. **All three lr candidates are trained: 1e-4, 3e-4, 1e-3.** Evaluation uses **only the 1,000 held-out TRAIN
  examples** (bf16 manual merge, as in the study). No eval-set scoring.
- Divergence (any of): a NaN/inf loss; tail-20% mean loss ≥ 0.9 × prior entropy; held-out accuracy < held-out majority + 10 pp.
- **lr_main** = the non-diverged candidate with the highest mean held-out accuracy over the two tasks (ties → smaller lr). If all diverge: the best mean held-out
  accuracy, documented. It applies to all tasks and seeds. Written to `pilot/pilot_decision.json` (hashed) before main training, which asserts it.

### 1b. Seed rule (decided automatically from the pilot)
- Projected core cost (formula in `prereg_e4b.json → pilot.cost_rule`) = pilot + 2-seed training (sec/step line fitted on the two pilot tasks, sequential, no concurrency credit)
  + stage0/1 (0.6 h) + P merges + S2 merges + E3 subset (merge cost from the measured bf16 forward throughput and probe token counts; E3 ≈ 3 × a stage-2 pair; 2 processes ≈ 1.5× speed-up).
- **Two seeds (primary P) iff the projected core ≤ 11 h**, otherwise **one seed (seed 0; primary R0)**, with no P/S1/S2/E3.

## 2. Integrity (every used seed; BEFORE predictors and merges)
- (a) E1b verbatim: eval metric ≥ majority baseline + 10 pp; STS-B Spearman ≥ 0.70.
- (b) **Not applicable**: no citable published Qwen2.5-0.5B dev-set references exist for these tasks and this setup, so rule (b) is dropped for E4b.
- (c) fp32 manual merge (W0 + ΔW, own head, last-token pooling) vs the fp32 `PeftModel` logits on the first 64 eval examples (unpadded, TF32 off). The tolerance is
  ≤ 1e-3 × max(1, max|logit|). A relative tolerance is used because decoder logits are unnormalized and 24 layers accumulate rounding; E1b's 1e-4 absolute was calibrated on BERT.
- (c2) precision check: the single adapter's held-out metric with **bf16** merged weights (study precision) is within **1 pp** of the fp32 value.
- Structural: 168 LoRA layers; head (num_labels, 896) with no bias; r/α; index sha256; main-run adapter of the right seed.
- **Exclusion**: a task failing in any used seed is removed from every population. **STOP if < 10 valid tasks.** Singles come from stage0 (bf16, the same code path as the merges).

## 3. Populations
- Two seeds:
  - **P — PRIMARY**: mixed-seed cross-task pairs; the alphabetically first task uses seed 0 (t1), the other seed 1 (t2) (E1c rule).
  - Secondary: **R0** seed-0 cross-task pairs (E1b order); **S1** seed-1 cross-task pairs; **S2** same-task pairs t@s0 × t@s1 (+ E3 subset).
  - Pooled 3-population summary (exploratory).
- One seed: **R0 — PRIMARY**. Nothing else.

## 4. Predictors
E1b/E1c `compute_predictors` (float64) over the 168 layers (B is d_out × 8; d_out ∈ {896, 128, 4864}). The predictors: **O_A**, **tv_cosine**, mean/min θ_min,
number of layers with θ_min < 30°, sign conflict (top 20% and all), norm ratio, null z of O_A (1,000 random rank-8 pairs per layer). O_B is dropped (identical to O_A).
Frozen in `predictors_e4b.sha256` before any merge.

## 5. Merges
- E1b §4 for every pair: TA W0 + λ(ΔW1 + ΔW2) on the 168 layers, each side with its own head, λ ∈ {0.3, 0.5, 0.7, 1.0}, chosen per pair on the two held-out sets
  (ties → smaller λ). **D = 1 − mean normalized eval score at λ\***. Exploratory TIES-lite and the θ★ = 30° gate are as in E1b.
- **Precision:** the merged weights are bf16(W0 + λΔ), with Δ computed in fp32. W0 is the bf16 checkpoint (exact); the head is fp32; eval batch 128.
  Singles use the same path, and (c2) checks bf16 vs fp32.
- E3 subset on S2 (two seeds only): `e3.py run()` + `merges.py` unmodified, the encoder swapped for the Qwen class (same interface), A2 grids,
  TA / PICO_TA / GATE / FORCEGATE.

## 6. Analysis
Identical to E4a §6 (the statistics are verbatim E1c `pop_stats`):
- **H1** ρ(O_A, D) > 0 and **H2** ρ(tv_cosine, D) > 0 on the **primary population**.
- 10,000-relabeling permutation p (one-sided), **Holm over {H1, H2}**, task-block bootstrap 2,000, LOTO.
- **PASS** iff ρ ≥ 0.4 ∧ Holm p < 0.05 ∧ ≥ 75% LOTO ρ > 0.2. **FAIL** iff not PASS ∧ bootstrap upper < 0.3. Otherwise **INCONCLUSIVE**.

Secondary: the other populations with the rule applied descriptively; pooled summary; θ_min distribution; gate firings; O_A vs the random null; shared-vs-mixed O_A;
reliability of D/O_A/cos/λ\* across seed configurations; S2 + E3 contrasts; fixed-λ ρ; secondary predictors; TIES-lite/gate vs TA.
Cross-backbone Spearman vs E1b R0 and E1c P (BERT) and vs E4a R0/P (RoBERTa), on common task pairs.

**Reading fixed in advance:**
- H1 FAIL (or INCONCLUSIVE with ρ ≤ 0) → the null extends to a decoder LLM.
- PASS → the overlap predictor works on this decoder, contrary to BERT; both are reported.
