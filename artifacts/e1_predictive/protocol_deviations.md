# E1 protocol deviations and pre-declared decisions

Written 2026-09-25 ~19:40 KST, **after Stage 0 and before Stage 1 (predictors) and Stage 2 (merges)**. Not edited after any merge result was seen. Machine-readable copy: `protocol_decisions.json`.

1. **Hardware: GPU, not CPU.** E1 runs on ubuntu-4070 (RTX 4070 Ti SUPER 16 GB, conda env `torch`: torch 2.11.0+cu128, transformers 5.17.0, peft 0.21.0, datasets 5.0.1), not on the box CPU. So **full GLUE validation is used for every task (no 5000-example cap)**, and the CPU-budget cap plan is dropped. (A CPU venv was installed on the box at /workspace/lora-paper/e1/.venv before the plan changed; install log: /workspace/lora-paper/e1/install.log. It was not used for any result.)
2. **7 tasks, 21 pairs, not 8 tasks and 28 pairs.** The Hub user prateeky2806 has **no STS-B LoRA adapter** (the full bert-base-uncased listing is in stage0.json: cola, mnli, mrpc, qnli, qqp, rte, sst2, wnli; no stsb). Section 6 says the "actual list is fixed in Stage 0", so STS-B and its 7 pairs are left out. WNLI was **not** used as a substitute because it is not in the pre-registered task list. Because of this, the Spearman-on-STS-B metric rule never applies.
3. **LOTO threshold adapted from 6 of 8 to 6 of 7.** With 7 tasks there are 7 leave-one-task-out rhos. PASS needs **at least 6 of 7 > 0.3**. This keeps the pre-registered fraction of at least 75% (5.25, rounded up to 6), so it is slightly stricter than 6 of 8.
4. **Permutation test sidedness:** the verdict uses the **two-sided** task-label permutation p (10000 random relabelings, seed 0). This is the conservative choice. The one-sided p and the exact p over all 7! = 5040 relabelings are also reported. With 7 tasks, only 5040 distinct relabelings exist, so the 10000 random draws include repeats.
5. **Segment (token_type) ids are all zeros (Stage-0 integrity fix).** With standard BERT segment ids, the pair-input adapters scored far below their cards and below this repo's own earlier numbers (MNLI 0.705, MRPC 0.716, RTE 0.560 with F1 0.13). With all-zero segment ids they give MNLI 0.807, MRPC 0.860, QNLI 0.908, QQP 0.894, RTE 0.614. Single-sentence tasks do not change. With zero segment ids, MNLI matches the repo's earlier self-reproduction (first 512 val: 0.8105 vs 0.811). Conclusion: the adapters were trained without segment ids. The earlier repo pipeline (`lora_merge_cert/eval.py`) also sends no token_type_ids. The diagnostic is kept in `diag/diag_tt.json`, and the superseded Stage-0 run is kept in `diag/stage0_with_bert_segment_ids/`. This choice was made before any predictor or merge was computed.
6. **Model-card comparison (section 6 INVALID rule) is applied literally, as instructed.** Full-val shortfalls over 2pp vs the card: **CoLA (MCC 0.606 vs 0.6347, 2.9pp), SST-2 (0.915 vs 0.98, 6.5pp), QQP (0.894 vs 0.95, 5.6pp), MNLI (0.807 vs 0.85, 4.3pp)**. So the pre-registered verdict label is **INVALID**. Stage 3 still reports the statistical verdict (PASS/FAIL/INCONCLUSIVE) separately. Caveat: this is not a like-for-like comparison. Each card's "evaluation set" is a **100-example hold-out carved from GLUE train**, not GLUE validation. Evidence: steps/epoch = ceil((n_train - 100)/32) for cola 265, mrpc 112, rte 75, mnli 12269, and the metrics come in 2-decimal steps. That exact hold-out could not be identified: train[:100], train[-100:], and train_test_split(100, seed in {28, 42, 0}) do not reproduce the cards, and the seed-0 split is clearly training data. The binomial SE with n=100 is about 2 to 3.6pp. The pipeline itself is validated by (a) logit equivalence to `PeftModel` (max |diff| < 1e-5 for all 7 adapters, which confirms the saved heads are loaded) and (b) the MNLI self-reproduction within 0.05pp.
7. **Metric = accuracy for every task**, as pre-registered, including CoLA (MCC is recorded as extra) and MRPC/QQP (F1 recorded as extra).
8. **Merge details:** each merged encoder uses W0 + lam*(dW1 + dW2) for all 73 LoRA layers (12 x {query, key, value, attention.output.dense, intermediate.dense, output.dense} + pooler.dense). dW = (alpha/r)*B@A = 2*B@A. Each task is evaluated with its **own saved classifier head**. No adapter saves a separate pooler (modules_to_save = null; PEFT SEQ_CLS stores the classifier). The pooler is updated only through its LoRA delta.
9. **lam selection ties** go to the smallest lam. Selection uses seed-0 1000-example TRAIN subsets, as pre-registered. These subsets overlap the adapters' own training data (for example, single MRPC train1k accuracy is 0.993). This is inherent to the protocol.
10. **Exploratory additions (not used for selection or the verdict):** validation scores for all 4 lam values, which give an exploratory rho at each fixed lam. Extra uncorrected predictors: count of layers with theta_min < 30 deg, minimum theta_min, untrimmed sign-conflict rate, norm ratio. The example-level bootstrap (1000 reps) from section 6 is reported for the primary rho.
11. **Known properties of predictors, stated in advance:** (a) def B (top-r left singular vectors of B@A) spans the same space as def A (orth(B)) whenever A has full row rank, so O_B should equal O_A up to numerics. (b) Every pair shares the same layer shapes, so the random-subspace null is the same for all pairs. That makes the null z-score a linear transform of O_A, with the same rho.
12. **Sign-conflict definition (TIES):** trim each flattened encoder task vector to its top 20% |entries|, then take the fraction of coordinates kept in both vectors that have opposite signs.
13. **Task-block bootstrap:** 2000 reps (seed 0). A rep is skipped if it yields fewer than 4 distinct task pairs. The skip count is reported.
